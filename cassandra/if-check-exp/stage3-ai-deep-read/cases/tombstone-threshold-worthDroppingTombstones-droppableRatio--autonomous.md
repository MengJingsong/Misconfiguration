| Estimate | `negative`. `tombstone_threshold` is a trigger heuristic for single-SSTable tombstone compactions, not a cap: it compares an estimated ratio and, when exceeded, merely makes one SSTable eligible; nothing bounds disk to a function of it. |
| Ground | The check only gates eligibility. It is further gated by `tombstone_compaction_interval` (L404), `gc_grace`/`gcBefore` (tombstones younger than gcBefore are not droppable), an overlap check (L415-445), and in STCS it runs only when no normal bucket is found (SizeTieredCompactionStrategy.java:91-105). A ratio at or below the threshold leaves any amount of tombstone/shadowed data on disk indefinitely. Also, the ratio is a fraction of an SSTable's cells, so it does not translate to a byte or disk limit. |

## A. Constraint trace

**A1. The constraint.** `tombstone_threshold`, a per-table compaction subproperty (CQL `WITH compaction = {'class': ..., 'tombstone_threshold': '0.2'}`). Kind: configuration entry (table schema option), stored in the strategy field `tombstoneThreshold` (`AbstractCompactionStrategy.java:86`). Option name declared at `:75`; default constant `DEFAULT_TOMBSTONE_THRESHOLD = 0.2f` at `:69`. Parsed in the constructor at `:117-118` (`Float.parseFloat`, default if absent; on option parse failure fallback to default at `:129`). Unit: dimensionless ratio (droppable tombstones / estimated cells in the SSTable). Validation at `:448-465` only rejects negative or non-numeric values (message says "greater than 0" but code allows 0; values above 1 are accepted and make the check never pass). Set via `CREATE/ALTER TABLE ... WITH compaction`; schema change applies without restart (strategy is re-instantiated on schema reload; verify in B3). Not settable by yaml or `-D`.

**A2. What it caps.** Nominally it relates to disk (space held by droppable tombstones and shadowed data in SSTables). The quantity compared is `sstable.getEstimatedDroppableTombstoneRatio(gcBefore)` (`:407`), computed in `StatsMetadata.java:166-174` as `estimatedTombstoneDropTime.sum(gcBefore) / (estimatedCellPerPartitionCount.mean() * count())`. It is an estimate from SSTable metadata histograms, not a measured byte count.

**A3. Mechanism.** `worthDroppingTombstones` (`:397-446`):
1. Returns false if `disableTombstoneCompactions`, the never-purge system property, or the table's never-purge setting (`:399-400`).
2. Returns false if the SSTable is younger than `tombstone_compaction_interval` (default 86400 s, `:71`, `:404`).
3. Gets the ratio (`:407`); at `:408` returns false if `droppableRatio <= tombstoneThreshold`.
4. If `unchecked_tombstone_compaction` (`:412`) returns true.
5. Otherwise overlap check: no overlapping live SSTables returns true (`:415-419`); fully expired SSTables returns true (`:421`); else an estimate of the ratio over the non-overlapping key range must itself exceed the threshold (`:428-444`), and returns false if the estimate is not informative (`:428-432`).
Callers: STCS only if no bucket qualifies (`SizeTieredCompactionStrategy.java:91-105`, picks the largest candidate); LCS `findDroppableSSTable` (`LeveledCompactionStrategy.java:523-545`, also checks the threshold at `:539`); TWCS (`TimeWindowCompactionStrategy.java:163`). Outcome when met: one SSTable is rewritten alone, which can free disk. Outcome when not met: nothing happens. Bypasses/overshoot: tombstones within gc_grace are not droppable regardless; tombstones that cover data in other overlapping SSTables are not purged; threshold above 1 disables the mechanism; a normal STCS bucket takes priority, so the single-SSTable compaction may be starved. Temporary extra disk (the rewrite output) is needed during the compaction. UnifiedCompactionStrategy extends the class but no `worthDroppingTombstones` call found there (grep), so UCS likely does not use it.

**A4. Other consumers.** Disk is also used by live data, snapshots, hints, commit log, un-flushed/compacting SSTables during normal compactions, and non-droppable tombstones (within gc_grace or overlapped). `gc_grace_seconds` is the main determinant of when tombstones become droppable at all.

**A5. Evidence beyond the source.** CASSANDRA-6563 (overlap check disabled, referenced in comment at `:411`); Cassandra docs on compaction subproperties (`tombstone_threshold`, `tombstone_compaction_interval`, `unchecked_tombstone_compaction`): https://cassandra.apache.org/doc/5.0/cassandra/managing/operating/compaction/overview.html (cited from knowledge, not fetched).

## B. Verification solution

**B1. Claim under test.** (Stage-4 reading, A4: Confirmed has Effect `does not cap`; the residual ratio is bounded by X only on the path where every other gate is open, which B1 counts as a gate, not as a cap on disk bytes.) Disk usage of a table does not follow `tombstone_threshold`: lowering the threshold below the ratio only makes SSTables eligible for single-SSTable compaction; where other gates apply (interval, gc_grace, overlap) disk stays high independent of the threshold, and no byte-denominated cap exists. Refuted if disk consistently tracks the threshold in a bounded way (e.g. residual tombstone ratio always at or below threshold across gates).

### B2. Unit tier  <!-- amended 2026-10-26, see D1 (A1-A5) -->

**B2a. Environment and build.** JDK 11, Ant. Copy the tree to local disk with `copy-source.sh`, `ant build-test`. Test class in the local copy: `test/unit/org/apache/cassandra/db/compaction/TombstoneThresholdProbeTest.java` extending `CQLTester` (same package as `AbstractCompactionStrategy`, so the protected `worthDroppingTombstones` and `tombstoneThreshold` are reachable without reflection). Run with `ant testsome -Dtest.name=TombstoneThresholdProbeTest` (the build forks a 1 GiB JVM).

**B2b. Knobs.** `tombstone_threshold` X in {0.0, 0.2 (default), 0.5, 0.9, 1.5}, set by `ALTER TABLE ... WITH compaction = {...}` (STCS) and read back from the strategy field `tombstoneThreshold` after each ALTER (instrument check that the knob reached the strategy). Gates: `tombstone_compaction_interval` 0 (open) and 86400 (closed); `unchecked_tombstone_compaction` true and false; a second overlapping SSTable present or absent; `cfs.setNeverPurgeTombstones(true)` as the closed-gate control. `gc_grace_seconds=0`; autocompaction disabled on the test table so that only explicit calls compact.

**B2c. Workload (A1).** Per fraction f in {0.1, 0.3, 0.6, 0.9}: a fresh table `(k int PRIMARY KEY, v blob)`, N = 10000 partitions of a 100-byte value written with `UPDATE ... USING TTL 1 SET v = ?` for the first f*N keys and `UPDATE ... SET v = ?` (no TTL) for the rest, one flush, then a 2.5 s wait so the TTL'd cells have expired, so the SSTable holds exactly one cell per partition and f*N expiring cells. `UPDATE` is used, not `INSERT`: an `INSERT USING TTL` also writes a TTL'd row marker that `MetadataCollector.update(LivenessInfo)` (`:217-225`) adds to the drop-time histogram without adding a cell, which would make the ratio 2f. `gcBefore` is passed explicitly as `nowInSeconds + 3600`, so wall time and the 60 s histogram rounding (`STREAMING_HISTOGRAM_ROUND_SECONDS`, default 60) do not matter. The droppable ratio r is read from the SSTable before every decision and is expected near f.

**B2d. Observables and instruments.** `sstable.getEstimatedDroppableTombstoneRatio(gcBefore)` (r); `strategy.worthDroppingTombstones(sstable, gcBefore)` (boolean); `strategy.getNextBackgroundTask(gcBefore)` (task or null; with one SSTable and `min_threshold` 4 no bucket exists, so a task means the tombstone path); `sstable.onDiskLength()` and the sum over live SSTables of the table before and after `task.execute(ActiveCompactionsTracker.NOOP)`. Instrument checks: the strategy's `tombstoneThreshold` equals X after each ALTER; r for f=0.5 lies in [0.4, 0.6]; known-answer: with gates open and X=0.0, the boolean is true for every f. Not observable: the scheduler's choice among tables (cluster tier).

**B2e. Procedure.** 1) For each f, write, flush, wait, record r and the bytes. 2) Gates open (interval 0, unchecked true): for each X, ALTER, record the strategy threshold, the boolean and whether `getNextBackgroundTask` returns a task. 3) Closed gates, at f=0.6: interval 86400 for each X; interval 0 and unchecked false with a second SSTable (2000 other keys, no TTL, flushed; it overlaps the first SSTable's whole token range) for each X; interval 0 and unchecked false with a single SSTable (no overlap) for each X; `setNeverPurgeTombstones(true)` for each X. 4) Byte step, one fresh table per (f, X in {0.2, 0.9}) with gates open: if `getNextBackgroundTask` returns a task, execute it and record the live bytes after; if not, record bytes unchanged. 5) Positive control: per f, a fresh table at X=1.5: `cfs.forceMajorCompaction()` and the live bytes after (the workload can show reclaim when the compaction is forced).

**B2f. Predictions (A2).** (P1) With gates open, boolean == (r > (double)(float)X) in every cell (the float constant is promoted to double, so X=0.9 with r exactly 0.9 yields true); X=0.0 true for r > 0; X=1.5 false for every f. (P2) With interval 86400, false in every cell, including every cell where r > X. With unchecked false and an overlapping SSTable, false at f=0.6 for X in {0.2, 0.5, 0.9, 1.5} (the non-overlapping estimate is near zero), although r > X for X in {0.2, 0.5}; true at X=0.0, because `remainingColumnsRatio * droppableRatio > tombstoneThreshold` (`:444`) is true for any positive product (amended 2026-10-26, D1 A8). With unchecked false and no overlap, equal to P1. With never-purge on, false everywhere. (P3) Byte step: when a task ran, the live bytes after are (1-f) of the bytes before, within 0.08 absolute (f=0.6, X=0.2: 0.32 to 0.48); when none ran (for example f=0.6 with X=0.9, f=0.3 with X=0.5 and 0.9), bytes are unchanged although f*100 % of the cells are droppable. (P4) The forced compaction at X=1.5 gives (1-f) within 0.08 for every f.

**B2g. Conclusions (A2).**

| Observation | Meaning |
|---|---|
| P1 holds in every open-gate cell, P2 holds (at least one closed-gate cell has r > X and the boolean false), P3 holds and P4 holds | **Confirmed — does not cap**: the threshold is one gate of a trigger; bytes are unchanged when r is at or below X or a gate is closed, and the effect is a step at X, not a function of bytes |
| A closed-gate cell returns true with r > X (interval, overlap or never-purge not effective), with the same data a P1 cell true | **Refuted**: the threshold alone opens the compaction |
| Bytes after an executed task follow X rather than f (differ across X at the same f by more than 0.08), or bytes fall in a cell where no task ran | **Refuted**: usage follows the threshold continuously |
| P1 fails in an open-gate cell without a closed gate explaining it (for example r differs from the boolean's inputs) | Not confirmed (no matching row); report the cell |
| r is outside f +/- 0.1 for the 0.6 and 0.9 tables, or the strategy's threshold differs from X after ALTER, or the forced compaction (P4) does not reduce the bytes | **Not confirmed**: limit never reached or instrument not valid; no verdict on the claim |

**B2h. Controls.** The explicit `gcBefore` removes the clock; `setNeverPurgeTombstones(true)` is the disabled-compaction control (a system property cannot be toggled per test: `NEVER_PURGE_TOMBSTONES_PROPERTY_VALUE` is a static final); the forced compaction (P4) is the positive control: the same workload, instruments and table lose their droppable bytes when a compaction is forced, so flat bytes at high X are not a workload limitation.

Group A, written with 50 % TTL'd keys: `a05, a20, a40, a70, a150` with `tombstone_threshold` 0.05 / 0.2 / 0.4 / 0.7 / 1.5, `tombstone_compaction_interval` 60, `unchecked_tombstone_compaction` true; `adef` the same with no `tombstone_threshold` option (default 0.2). **B3c. Workload (A1, A5).** Per table, 200,000 partitions of a 200-byte random value (about 45 MB on disk), written by a driver with `UPDATE ... USING TTL 120` for the TTL'd keys (key index mod 100 below 50, or below 15 for group B) and plain `UPDATE` for the rest, then `nodetool flush ks t` and `nodetool disableautocompaction ks t`. 14 tables is about 650 MB, plus rewrites, on tmpfs. After the last write, wait until `last write + 120 s TTL + 60 s histogram rounding + 10 s gc_grace + 20 s margin` (210 s) so that every TTL'd cell is past gc_grace and the SSTables are older than the 60 s interval. Then record `du`, the SSTable ratio, and run `nodetool enableautocompaction ks t` for every table (this submits one background compaction check per table), observe 300 s with `du` every 30 s, then run `nodetool compact ks pc`.

**B3d. Observables and instruments.** `du -sb` of each table's data directory every 30 s (real disk bytes); `tools/bin/sstablemetadata --gc_grace_seconds 10 <Data.db>` "Estimated droppable tombstones" per table before the enable and after the window (the ratio the strategy compares, same formula as `SSTableMetadataViewer.java:362-363`); `nodetool compactionstats`; `system.log` lines for compactions of each table. Not observable: the strategy's value at decision time (sstablemetadata is the proxy).

**B3e. Procedure.** 1) Start the node; instrument check: `nodetool status` UN, `statusbinary` running, the tables exist with the intended compaction options (read back from `system_schema.tables`). 2) Create tables, load, flush, disable autocompaction; record `du` (peak) per table. 3) Wait 210 s; record the ratio per table and `du`. 4) Enable autocompaction on all tables at once; observe 300 s. 5) Record the ratio per table, then `nodetool compact ks pc` and the `du`. 6) Stop the node (`nodetool drain`, then kill by PID); confirm no `CassandraDaemon` of this run remains.

### D2. Stage-4 result, 2026-10-26

Results: [`results/tombstone-threshold-worthDroppingTombstones-droppableRatio--autonomous.md`](../../stage4-runtime-verification/results/tombstone-threshold-worthDroppingTombstones-droppableRatio--autonomous.md). Run 1 only, no run 2. Outcome class **true negative** (estimate `negative`, effect `does not cap`).

- **Unit: Confirmed (does not cap).** With the gates open `worthDroppingTombstones == (r > (double)(float)X)` in all 20 cells; with interval 86400, an overlapping SSTable plus `unchecked=false`, or never-purge on, it is false at r = 0.6 for X below r (the overlap cell at X = 0.0 is true, `:444`); an executed task frees (1-f) of the bytes (0.689, 0.392, 0.097) whatever X (0.2 or 0.9), and with r at or below X nothing is reclaimed although 10 to 60 % of the cells are droppable; a forced compaction at X = 1.5 frees (1-f) (positive control).
- **Cluster: Confirmed (does not cap).** 14 tables of 44.7 MB: at 50 % TTL'd cells X = 0.05, 0.2, 0.4 and the default end at 0.483 of the peak (the same value), X = 0.7 and 1.5 stay at 1.000; at 15 % only X = 0.05 shrinks (0.842); the interval-gated table `gi` and the overlap-gated table `go` (X = 0.05) stay at 1.000 of their bytes with ratio 0.5, ten times X, for the 300 s window; `nodetool compact` on `pc` (X = 1.5) frees the same 0.483.
- **The claim B1 needs one qualifier:** with every gate open an SSTable above X is rewritten, so its residual droppable ratio is at most X; the claim holds for the byte limit and for the gated paths, not for that single-gate path. Memtable pressure split each cluster table into two SSTables (one is the intended design); both carry the same ratio and compact alone, no row depends on it.
- **Two things the filed text got wrong, found in the audit:** a delete-into-a-second-SSTable workload cannot give r = f (tombstone SSTable r near 1, data SSTable 0, and its tombstones cannot be purged while the data SSTable overlaps), and an `INSERT USING TTL` counts its row marker in the drop-time histogram without a cell, giving r = 2f (use `UPDATE`).
- **Upstream or documentation candidates:** the error text of the option (`greater than 0`) accepts 0, and a value above 1 silently disables the mechanism (`validateOptions`, `:448-465`); `tombstone_compaction_interval` and the overlap gate are not mentioned beside `tombstone_threshold` in the option's documentation as conditions that keep a droppable share above the threshold.
