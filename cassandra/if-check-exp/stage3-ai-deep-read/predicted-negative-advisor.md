# Predicted negative — groups from band D, Set B (`advisor-run`)

Mirrors [`predicted-negative.md`](predicted-negative.md) for the advisor's session. **Do not edit `predicted-negative.md`.**
An entry here is a **group of band D rows the autonomous agent estimated `negative` for the same reason**, read with the Cassandra source
open. A group is a queue, not a final refusal: any uid in it can be promoted to a case file (the guided agent writes it, with estimate
`negative`, a ground and a verification solution that tests that usage does not follow the constraint), and then its uid's
`pointer` in `band-d-progress-setB.csv` names the case file and the group lists it as promoted.

A line already judged in `predicted-negative.md` is cited there (`see predicted-negative.md, <batch>`), not recorded again.
Add the group here after the bookkeeping step of a batch ([`HANDOFF-ADVISOR.md`](../../../HANDOFF-ADVISOR.md) §5.3).

## Group format

```
### G<number> — <one-line ground> (<module>, <source file or files>)

- **Ground:** why usage should not follow the constraint, naming the kind of operand (a thread count, a clock value, a
  per-request length that is the row's own size, a loop bound, ...) — one to three sentences.
- **Rows (N):** `uid`, `uid`, ...   (every uid of the group; they are the `pointer` G<number> in the progress file)
- **Worked example:** `uid` — what the check compares, where each operand comes from (`file:line` in `~/cassandra-src`),
  and why the ground holds for this row.
- **Why the rest follow:** one sentence on what makes the other rows the same case (the same helper, the same operand type).
- **Promoted to a case file:** none  (or `uid` → `cases/<stem>--guided.md`)
- **Weakest point:** one sentence on what in the ground is least certain (used to choose groups for the guided pass).
- **Session / date:** model, date.
```
