**A1. The constraint.** The line at SafeMemoryWriter.java:52 (`newCapacity != capacity()`) is only a no-op guard (skip the copy if the size is unchanged; `capacity()` is `memory.size()` at SafeMemoryWriter.java:89-92), so it is not itself a limit. The value it compares is produced by `expandToFit` (SafeMemoryWriter.java:45-48) -> `DataOutputBuffer.calculateNewSize` (DataOutputBuffer.java:158-171), and the only memory-related constraints on that value are two settings. The first is the growth threshold `DOB_DOUBLING_THRESHOLD_MB`, a JVM system property (CassandraRelevantProperties entry `cassandra.DOB_DOUBLING_THRESHOLD_MB`, first declared at config/CassandraRelevantProperties.java:203). It is read into the static constant `DOUBLING_THRESHOLD` (DataOutputBuffer.java:48), which is used at DataOutputBuffer.java:164: once the current capacity exceeds 1024*1024*DOUBLING_THRESHOLD bytes, the buffer grows by 50% (`capacity*3/2`) instead of doubling (`capacity*2`). The unit is megabytes and the default is the string "64" (CassandraRelevantProperties.java:203), so the default is a literal and is not derived from anything. It can only be set at startup with `-Dcassandra.DOB_DOUBLING_THRESHOLD_MB=<n>`, because it is read once into a static final field; there is no cassandra.yaml key and no JMX setter, and a change needs a restart. It controls growth rate rather than an absolute cap. The second is a hard ceiling, the constant `MAX_ARRAY_SIZE = Integer.MAX_VALUE - 8` (DataOutputBuffer.java:118). It is enforced through `validateReallocation` (DataOutputBuffer.java:150-154), which throws BufferOverflowException when the new size does not exceed the current capacity after saturation by `saturatedArraySizeCast` (DataOutputBuffer.java:121-125). It is a fixed constant in bytes (about 2 GiB) and cannot be set.
