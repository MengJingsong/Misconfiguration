[details](runs/p1-hadoop-2026-11-24.md#oc-2) | — | open |
| OC-3 | 2026-11-24 | `CachePoolInfo_limit-rescanFile-pool.getLimit--autonomous` | autonomous | DataNode native memory and mappings: each cached replica is its own mmap, and the reservation is page-rounded, so tiny files admitted by a byte limit give one mapping per file. About 65k cached small blocks (a DN cap of about 256 MiB or more) can exhaust Linux vm.max_map_count (65530), after which DataNode native allocations fail with OutOfMemoryError (for example 'unable to create native thread'). [details](runs/p1-hadoop-2026-11-24.md#oc-3) | — | open |
| OC-4 | 2026-11-24 | `CachePoolInfo_limit-rescanFile-pool.getLimit--autonomous` | guided | DataNode centralized cache: one mmap (VMA) plus mlock per cached block. The pool limit counts file bytes (1 B for a 1-byte file), the DN cap counts page-rounded bytes (4 KiB), and nothing counts mappings, so a pool of tiny files can use up vm.max_map_count (65530) and the DN's native allocations then fail. [details](runs/p1-hadoop-2026-11-24.md#oc-4) | CP-1, CP-9 | open |
| OC-5 | 2026-11-24 | `CachePoolInfo_limit-rescanFile-pool.getLimit--autonomous` | guided | The DataNode cache's mlocked memory sits outside -Xmx and the direct-memory limit, and dfs.datanode.max.locked.memory is checked only against RLIMIT_MEMLOCK, not against RAM, the container or the DN heap.
