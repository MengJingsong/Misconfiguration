**Instrument checks (not readings; outputs in `~/s4-b9-rp-logs/shake-*` on `pc07`, not used):**
1. `analyze_unit.py` on a synthetic good file: 0 primary mismatches; on the bad copy (N=10 caches 15 rows): flags `cachedLiveRows` and the size ratio, class "claim wrong".
2. Unit test at 300 rows per partition (`unit-run.sh ... 300`): runs, first trigger OK, all `cachedLiveRows` follow N; the only mismatches are the ones that depend on the 1000-row size (ALL and 2000 store 300 rows).
3. Cluster chain on 400 + 80 partitions: load, known-answer reads, arms. **Defect found and fixed before run 1:** the first version of `loader.py scan` used a prepared statement. After a node restart the prepared statement (restored from the earlier lifetime) kept the table's old `rows_per_partition`, so an `ALTER TABLE` to N=1 still cached 100 rows per partition (39.6 MiB for 400 partitions), and the 32 MiB arm cached nothing (stale N=NONE). A `cqlsh`-style unprepared statement follows the new setting at once. The scan now uses unprepared statements; the reads are parsed on every call. Checked directly on a hand-started node with `TRACING` (`Caching 7 rows` / `Caching 3 rows` after `ALTER`).
4. **Second defect found and fixed before run 1 (baseline):** over 400 partitions of N=10 (4 MB of cache) `RssAnon` grew by 64-84 MB, and 33 MB at N=1 (0.5 MB of cache). The one-off native memory of the first whole-partition reads (not the cache) was in the delta. `cluster-run.py` now takes a `cold` checkpoint after 20 s idle, then reads 1,000 whole partitions of the *other* table (row cache off for it) as a warm-up, waits 10 s, and takes the `baseline` checkpoint that the RSS check uses. After the change the same shakedown showed N=1: +7.6 MB for 0.5 MB of cache and N=100: +48.8 MB for 41.5 MB. Both checkpoints are kept in `ckpt.jsonl`; the warm-up does not touch the table under test, its cache or the counters (the counters are read from the table under test only). The warm-up is a harness step, not part of the frozen text (B3f says "the arm's baseline").
5. Shakedown on 400 + 80 partitions (arms n10 n1 n100 nall t10 none c32, `analyze_cluster.py ... 400 80`): every arm ran, first-trigger checks passed, e(N) ratios 1.10 / 0.98 / 0.97 (N=1, 10, 100), e(ALL) 304 KiB, none = 0, c32 227 entries under 32 MiB, t10 above n10 by 2.4 KB. The remaining mismatches there are the ones that need the full 10,000 partitions (cap not reached at 400 partitions, `ks.t` size note).
