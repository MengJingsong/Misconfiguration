## A. Constraint trace

**A1. The constraint.** Global row cache capacity. Configuration entry `row_cache_size` (`conf/cassandra.yaml:564`, declared [`Config.java:473-474`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/config/Config.java#L473-L474), default `0MiB` = disabled), read via `DatabaseDescriptor.getRowCacheSizeInMiB()` ([`DatabaseDescriptor.java:3916-3919`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/config/DatabaseDescriptor.java#L3916-L3919)). Provider class `row_cache_class_name` ([`Config.java:472`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/config/Config.java#L472), default `org.apache.cassandra.cache.OHCProvider`; alternative `SerializingCacheProvider`). Runtime-settable without restart via JMX `RowCacheCapacityInMB` (`service/CacheServiceMBean.java:54`) or `nodetool setcachecapacity <key> <row> <counter>` (`tools/nodetool/SetCacheCapacity.java:30-42`, `tools/NodeProbe.java:1088-1094`). Unit MiB, multiplied by 2^20 in the setter ([`CacheService.java:332`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/service/CacheService.java#L332)). Not written back to `DatabaseDescriptor`; restart reverts. If yaml size is 0, `NopCacheProvider` is installed ([`CacheService.java:146-147`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/service/CacheService.java#L146-L147)) and any non-zero runtime capacity throws `UnsupportedOperationException` (`cache/NopCacheProvider.java` `setCapacity`). The target line rejects negative input.


**Limit type (2026-10-29).** config: yaml entry. The traced constraint decides ([README §6](../../../stage3-ai-deep-read/README.md#6-rules-that-hold-for-both-agents)).
**A2. What it caps.** Off-heap (native) memory for OHC: compared quantity is OHC's used memory (`ohCache.memUsed()`, exposed as `weightedSize`, `cache/OHCProvider.java:97-100`), i.e. serialized key + serialized partition + per-entry header. For `SerializingCacheProvider` the weight is the serialized size in `RefCountedMemory` (off-heap) under a Caffeine `maximumWeight` (`cache/SerializingCache.java:46-75`).

**A3. Mechanism.**
1. Startup: `initRowCache` picks the provider ([`CacheService.java:141-162`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/service/CacheService.java#L141-L162)); `OHCProvider.create` sets `builder.capacity(rowCacheSizeInMiB<<20)` with `throwOOME(true)` ([`OHCProvider.java:37-46`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/cache/OHCProvider.java#L37-L46)).
2. Runtime: setter → guard (target) → `rowCache.setCapacity` → `InstrumentingCache.setCapacity` (`cache/InstrumentingCache.java:82-85`) → `OHCacheAdapter.setCapacity` → `ohCache.setCapacity` ([`OHCProvider.java:62-65`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/cache/OHCProvider.java#L62-L65)); OHC evicts to the new capacity.
3. Inserts: on a row cache miss for a table whose `caching.rows_per_partition` is not NONE, `SinglePartitionReadCommand` puts a sentinel, reads the head of the partition, then replaces it with the `CachedPartition` (`db/SinglePartitionReadCommand.java:542-600`). OHC serializes it off-heap and evicts LRU entries in that segment while used > segment capacity.
4. Outcome at the limit: eviction; entries larger than OHC's maximum entry size (a fraction of a segment) are not stored. No error to the client.
5. Overshoot: OHC hash-table/segment structures and in-flight serialization buffers are outside the capacity (`conf/cassandra.yaml:556-560` says so explicitly); per-segment enforcement means total use ≤ capacity but individual segments fill unevenly.

**A4. Other consumers.** Off-heap: chunk cache (`file_cache_size`, if enabled), memtable off-heap allocation, networking buffer pools, bloom filters, index summaries, compression metadata, direct buffers, JVM metaspace/threads. These all appear in process RSS.

**A5. Evidence beyond the source.** `conf/cassandra.yaml:543-564` (OHC overhead note, default 0); OHC README https://github.com/snazy/ohc (capacity per segment, eviction, max entry size); existing unit tests `test/unit/org/apache/cassandra/db/RowCacheTest.java:102`, `RowCacheCQLTest.java:33` use `setRowCacheCapacityInMB(1)`; test yaml enables 16 MiB (`test/conf/cassandra.yaml:44-45`).

## B. Verification solution

**B1. Claim under test.** With the row cache enabled, for any capacity C set by `setRowCacheCapacityInMB(C)` (or `row_cache_size: C MiB`), the row cache's used memory stays ≤ C×2^20 bytes while reading a data set many times larger, and the process's off-heap footprint grown by the row cache scales with C; a negative C is refused.
