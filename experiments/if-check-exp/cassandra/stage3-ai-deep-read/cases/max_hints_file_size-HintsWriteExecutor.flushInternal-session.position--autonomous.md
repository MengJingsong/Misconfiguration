## A. Constraint trace

**A1. The constraint.** `max_hints_file_size` (configuration entry). First declared at `src/java/org/apache/cassandra/config/Config.java:447` (`public DataStorageSpec.IntMebibytesBound max_hints_file_size = new DataStorageSpec.IntMebibytesBound("128MiB");`, with the legacy-name `@Replaces(oldName = "max_hints_file_size_in_mb", ...)` at Config.java:446). Unit: MiB in yaml (min unit MiB; `conf/cassandra.yaml:106` `max_hints_file_size: 128MiB`, documented at :104-105). Default 128 MiB is a hard-coded literal in Config.java:447 (no derivation). Read through `DatabaseDescriptor.getMaxHintsFileSize()` (DatabaseDescriptor.java:3718-3721, `conf.max_hints_file_size.toBytesInLong()`). Settable only in cassandra.yaml (non-volatile field, no setter in DatabaseDescriptor, no JMX/nodetool: `grep -n max_hints_file_size DatabaseDescriptor.java` shows only :3720); a change needs a node restart. Validated in `DatabaseDescriptorTest.java:368` (int-range test).

**A2. What it caps.** Resource: disk (the size of a single hints file under `hints_directory`, default `$CASSANDRA_HOME/data/hints`, DatabaseDescriptor.java:644-646). Quantity compared: `session.position()` = `initialSize + bytesWritten` (HintsWriter.java:189-192), where `initialSize` = `channel.size()` of the file when the session opened (HintsWriter.java:136-141, ctor :173-181) and `bytesWritten` is the sum of `hint.remaining()` appended so far in this session (HintsWriter.java:200-202). It is a per-file byte count, not a per-host or per-node total, and not memory.

**A3. Mechanism.** **[Amended 2026-10-26, stage-4 step-0 audit: citation fixes, none changes the trace: `flushBuffer` is HintsWriteExecutor.java:83-86 (not :100-103; :99-102 is `flushBufferPool(pool, stores)`), `HintsBuffer.create` is HintsBuffer.java:75-78, `openWriter()` HintsStore.java:307-320, `Session.close()` HintsWriter.java:269-275, the `DatabaseDescriptor.setMaxHintsSizePerHostInMiB` setter :3590-3593. All other cited lines (Config.java:446-448, HintsWriteExecutor.java:50,60,222-231,239-248, HintsWriter.java:68-95,136-141,174-192,202, HintsStore.java:259-272,295-300,322-330, HintsService.java:79,110-122,161-169,253-258, StorageProxy.java:2442-2501, DatabaseDescriptor.java:3718-3721, cassandra.yaml:104-115) were re-read and hold. The periodic flush and `flushAndFsyncBlockingly` also reach `flush(Iterator, HintsStore)` (PartiallyFlushBufferPoolTask, HintsWriteExecutor.java:~190-205), so every write path passes :247]**
1. Hints reach disk via `HintsService.write()` (HintsService.java:161-169) into a direct `HintsBuffer` slab (`HintsBuffer.create`, HintsBuffer.java:74-77; slab size `max(getMaxMutationSize()*2, 32 MiB)`, HintsService.java:79, :110-111), flushed by the periodic task (`hints_flush_period`, HintsService.java:116-122) or when a slab fills, through `HintsWriteExecutor.flushBuffer` (:100-103, `FlushBufferTask` :130-150) -> `flush(HintsBuffer)` (:217-220) -> `flush(Iterator, HintsStore)` (:222-231).
2. `flush(Iterator, HintsStore)` loops `while (iterator.hasNext())` calling `flushInternal(iterator, store.getOrOpenWriter())`; if it returns false, `store.closeWriter()` (HintsWriteExecutor.java:222-231).
3. `flushInternal` reads the limit once per call (`long maxHintsFileSize = DatabaseDescriptor.getMaxHintsFileSize();` :239), opens a `Session` over the shared 256 KiB direct `writeBuffer` (:241, buffer allocated at :60 with `WRITE_BUFFER_SIZE = 256 << 10` :50), appends each hint (:245) and then tests `session.position() >= maxHintsFileSize` (:247). True -> `return false` (:248), which closes the session (try-with-resources: `Session.close()` flushes, may fsync, records `descriptor.hintsFileSize(position())`, HintsWriter.java:268-275) and then the file. False for all hints -> `return true`, file stays open for the next flush.
4. `closeWriter()` (HintsStore.java:322-330) closes the file and enqueues its descriptor for dispatch (`offerLast`); the next loop iteration opens a new file (`openWriter()` :308-320, `HintsWriter.create` HintsWriter.java:68-95).

Outcomes at the limit: the current file is closed and a new one started; nothing is dropped, blocked or rejected. Overshoot paths: (a) the test is after `append`, so a file ends at limit + (at most one hint, <= max_mutation_size-derived size) ; (b) the compare is `>=` against position including the file header (descriptor bytes written at HintsWriter.java:83-84); (c) a file that is not full at the end of a flush stays open and is only topped up by later flushes, each starting a new Session with `initialSize = channel.size()`; (d) with compression/encryption (`CompressedHintsWriter`, `EncryptedHintsWriter`, HintsWriter.java:87-90) `bytesWritten` counts the pre-compression `hint.remaining()` handed to `append`, while the file size after compression can differ (to verify only if compression is enabled; run uncompressed by default). No bypass by which a file is exempt, but there is no path by which the knob limits the number of files.

**A4. Other consumers.** Total hints disk is bounded instead by (i) `max_hint_window` (Config.java:115, default 3h; `shouldHint` StorageProxy.java:2461-2477 stops creating hints for a host down longer than this), (ii) `max_hints_size_per_host` (Config.java:448, default `0B` = disabled; check at StorageProxy.java:2488-2498 compares `HintsService.getTotalHintsSize(host)` (HintsService.java:253-258) -> `HintsStore.getTotalFileSize()` (HintsStore.java:259-272), summing queued files plus the open writer) which is checked only when a hint is created, so it overshoots by whatever sits in the in-memory buffer and is flushed afterwards, (iii) hint TTL / `auto_hints_cleanup_enabled` (cassandra.yaml:113-115). Memory sidecars unrelated to the knob: the 32 MiB (or 2x max_mutation_size) direct `HintsBuffer` slab(s) (HintsBuffer.java:77) and the 256 KiB direct `writeBuffer` (HintsWriteExecutor.java:60).

**A5. Evidence beyond the source.** Cassandra docs (hints section, "max_hints_file_size" in cassandra.yaml reference) describe it as "Maximum size for a single hints file" (matches cassandra.yaml:104-106 in the tree). The per-host cap (`max_hints_size_per_host`) was added in a later Cassandra release than the per-file limit; no issue ID relied on (not fetched). Otherwise `none`.

## B. Verification solution

**B1. Claim under test.** Changing `max_hints_file_size` changes only how many hint files the same hints are split into (and the per-file size, which stays within [limit, limit + one hint]); it does not change the total hint bytes on disk for a host, nor direct-memory use. The total on disk is instead governed by `max_hints_size_per_host`/`max_hint_window`. Refuted if the total hints bytes on disk moves in proportion to (or is bounded by) `max_hints_file_size`.
