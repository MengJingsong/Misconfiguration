## A. Constraint trace

**A1. The constraint.** Global counter cache capacity. Configuration entry `counter_cache_size` (`conf/cassandra.yaml:595`, declared [`Config.java:479-480`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/config/Config.java#L479-L480), default `null`), resolved in `DatabaseDescriptor.applySimpleConfig` ([`DatabaseDescriptor.java:832-845`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/config/DatabaseDescriptor.java#L832-L845)): `null` = auto `min(max(1, 2.5% of Runtime.totalMemory() MiB), 50)` MiB; negative rejected. Runtime-settable without restart via JMX `CounterCacheCapacityInMB` (`service/CacheServiceMBean.java:58`) or `nodetool setcachecapacity <key> <row> <counter>` (`tools/nodetool/SetCacheCapacity.java:30-42`, `tools/NodeProbe.java:1088-1094`). Unit MiB, ×2^20 in the setter ([`CacheService.java:349`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/service/CacheService.java#L349)). Not written back to `DatabaseDescriptor`. The target line rejects negative input; 0 disables cache use (`db/ColumnFamilyStore.java:2500-2511`, `db/CounterMutation.java:213`).


**Limit type (2026-10-29).** config: yaml entry. The traced constraint decides ([README §6](../README.md#6-rules-that-hold-for-both-agents)).
**A2. What it caps.** Heap. Compared quantity: Caffeine weighted size = Σ `CounterCacheKey.unsharedHeapSize() + ClockAndCount.unsharedHeapSize()` (`cache/CaffeineCache.java:61-69`; `cache/CounterCacheKey.java:152-157` = shallow + partition key array + cell name array; `db/ClockAndCount.java:46-49`).

**A3. Mechanism.**
1. Startup: `initCounterCache` → `CaffeineCache.create(counterCacheSizeInMiB<<20)` ([`CacheService.java:172-196`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/service/CacheService.java#L172-L196)), `maximumWeight` + weigher + `ImmediateExecutor` ([`CaffeineCache.java:51-58`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/cache/CaffeineCache.java#L51-L58)).
2. Runtime: setter → guard (target) → `counterCache.setCapacity` → `InstrumentingCache.setCapacity` (`cache/InstrumentingCache.java:82-85`) → `policy.setMaximum` ([`CaffeineCache.java:77-80`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/cache/CaffeineCache.java#L77-L80)).
3. Inserts: every applied counter update caches the new (clock, count) of each touched cell: `CounterMutation.updateWithCurrentValue` → `ColumnFamilyStore.putCachedCounter` → `counterCache.put` ([`CounterMutation.java:232-240`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/db/CounterMutation.java#L232-L240), [`ColumnFamilyStore.java:2506-2511`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/db/ColumnFamilyStore.java#L2506-L2511)). One entry per distinct counter cell, independent of the table's `caching` option. Saved-cache load also inserts (`CacheService.java` `CounterCacheSerializer`).
4. Outcome at the limit: W-TinyLFU eviction on the writing thread; no error.
5. Overshoot: Caffeine node/table/sketch overhead and shared `TableId` are not weighed; transient excess by in-flight puts.

**A4. Other consumers.** Heap: memtables (the counter values themselves), key cache, auth/prepared caches, counter write path locks (`counter_write` lock striping) and garbage.

**A5. Evidence beyond the source.** `conf/cassandra.yaml:581-595` (auto default; "only the local (clock, count) tuple ... relatively cheap"); `test/unit/org/apache/cassandra/db/CounterCacheTest.java:229-238` toggles capacity 0/1; Caffeine eviction docs https://github.com/ben-manes/caffeine/wiki/Eviction.

## B. Verification solution

**B1. Claim under test.** For any counter cache capacity C set by `setCounterCacheCapacityInMB(C)` (or `counter_cache_size: C MiB`), the counter cache's weighted size stays ≤ C×2^20 bytes (plus a few entries) no matter how many distinct counter cells are updated, and the retained heap of counter cache objects scales linearly with C; a negative C is refused.
