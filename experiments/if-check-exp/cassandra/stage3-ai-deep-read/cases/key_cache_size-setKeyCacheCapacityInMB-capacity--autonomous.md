## A. Constraint trace

**A1. The constraint.** Global key cache capacity. Kind: configuration entry `key_cache_size` (`conf/cassandra.yaml:525`, declared [`Config.java:467-468`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/config/Config.java#L467-L468), type `DataStorageSpec.LongMebibytesBound`, default `null`), resolved at startup in `DatabaseDescriptor.applySimpleConfig` ([`DatabaseDescriptor.java:815-823`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/config/DatabaseDescriptor.java#L815-L823)): `null` means auto = `min(max(1, 5% of Runtime.totalMemory() in MiB), 100)` MiB; negative values are rejected (`:819-828`). Also runtime-settable without restart via JMX `org.apache.cassandra.db:type=Caches` `KeyCacheCapacityInMB` ([`CacheServiceMBean.java:56`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/service/CacheServiceMBean.java#L56)) and `nodetool setcachecapacity <key> <row> <counter>` ([`SetCacheCapacity.java:30-42`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/tools/nodetool/SetCacheCapacity.java#L30-L42), [`NodeProbe.java:1088-1094`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/tools/NodeProbe.java#L1088-L1094)). Unit MiB; the setter multiplies by 1024*1024 ([`CacheService.java:341`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/service/CacheService.java#L341)). The runtime value is not written back to `DatabaseDescriptor`, so a restart reverts to the yaml value. The target line ([`CacheService.java:338-339`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/service/CacheService.java#L338-L339)) rejects negative input with `RuntimeException`; 0 is allowed and disables use ([`ColumnFamilyStore.java:3274`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/db/ColumnFamilyStore.java#L3274)).


**Limit type (2026-10-29).** config: yaml entry. The traced constraint decides ([README §6](../../../stage3-ai-deep-read/README.md#6-rules-that-hold-for-both-agents)).
**A2. What it caps.** Heap. The compared quantity is Caffeine's weighted size: sum over entries of `KeyCacheKey.unsharedHeapSize() + AbstractRowIndexEntry.unsharedHeapSize()` (`src/java/org/apache/cassandra/cache/CaffeineCache.java:61-69`; `KeyCacheKey.java:59-62` = shallow size + key byte array; `io/sstable/format/big/RowIndexEntry.java:200-202` for a non-indexed entry, `:613-617` for an indexed entry including its `IndexInfo` objects).

**A3. Mechanism.**
1. Startup: `CacheService.initKeyCache` builds `CaffeineCache.create(keyCacheSizeInMiB*1024*1024)` ([`CacheService.java:119-128`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/service/CacheService.java#L119-L128)), i.e. `Caffeine.newBuilder().maximumWeight(cap).weigher(...).executor(ImmediateExecutor.INSTANCE)` ([`CaffeineCache.java:51-58`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/cache/CaffeineCache.java#L51-L58)).
2. Runtime: `setKeyCacheCapacityInMB(c)` → guard `c < 0` throws (target) → `keyCache.setCapacity(c<<20)` ([`CacheService.java:341`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/service/CacheService.java#L341)) → `InstrumentingCache.setCapacity` (`cache/InstrumentingCache.java:82-85`) → `policy.setMaximum` ([`CaffeineCache.java:77-80`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/cache/CaffeineCache.java#L77-L80)); Caffeine evicts down to the new maximum immediately.
3. Inserts: BIG-format readers call `KeyCacheSupport.cacheKey` → `KeyCache.put` → cache `put` (`io/sstable/keycache/KeyCacheSupport.java:80-87`; `BigTableReader.java:343,393`). With `ImmediateExecutor`, Caffeine's maintenance (eviction by W-TinyLFU) runs on the calling thread after the write, so the weighted size exceeds the maximum only transiently (by roughly the entries written concurrently).
4. Outcome at the limit: older/colder entries are evicted; the new entry may itself be rejected by the admission policy. No error.
5. Bypasses/overshoot: (a) the weigher counts only `unsharedHeapSize`, not Caffeine's node, hash-table and frequency-sketch overhead, nor the shared `Descriptor`/`TableId` objects, so real heap per entry is larger than the weight by a roughly constant amount; (b) a single entry heavier than `Integer.MAX_VALUE` throws ([`CaffeineCache.java:65-67`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/cache/CaffeineCache.java#L65-L67)); (c) the key cache is only used by formats that support it (BIG; `KeyCacheSupport.isSupportedBy`, [`KeyCacheSupport.java:93-96`](https://github.com/apache/cassandra/blob/cassandra-5.0.9/src/java/org/apache/cassandra/io/sstable/keycache/KeyCacheSupport.java#L93-L96)); with `sstable.selected_format: bti` (`conf/cassandra_latest.yaml:1165`) the knob governs nothing.

**A4. Other consumers.** Other heap users outside this cap: memtables, row index summaries (`index_summary_capacity`), counter cache, auth/prepared-statement caches, read/write path garbage. The chunk cache and row cache (OHC) are off-heap.

**A5. Evidence beyond the source.** `conf/cassandra.yaml:517-525` (auto default, "Set to 0 to disable"); Caffeine eviction docs, https://github.com/ben-manes/caffeine/wiki/Eviction (weight-based maximum, eviction may briefly exceed); `nodetool info` prints Key Cache size/capacity (`src/java/org/apache/cassandra/tools/nodetool/Info.java:93-101`); metrics `Capacity`/`Size`/`Entries` (`src/java/org/apache/cassandra/metrics/CacheMetrics.java:69-71`); virtual table `system_views.caches` (`db/virtual/CachesTable.java:77`).

## B. Verification solution

**B1. Claim under test.** For any key cache capacity C set through `setKeyCacheCapacityInMB(C)` (or `key_cache_size: C MiB`), the key cache's weighted size stays at or below C×2^20 bytes (plus at most a few entries' weight) however many distinct keys are read, and the retained heap of key cache objects scales linearly with C; a negative C is refused.
