# U7 — stage 3-b client trigger check (2026-11-23)

**Case:** [`in_select_cartesian_product--modification-IN-product-row-build`](../cases/in_select_cartesian_product--modification-IN-product-row-build/in_select_cartesian_product--modification-IN-product-row-build.md)
(true positive, `verified-OOM · deployment`). Stage 3-a: [`U7.md`](../stage3-jira-check/U7.md) (`new`). Analysis only (no node run).

**Mechanism.** One prepared `UPDATE … WHERE k IN ? AND c IN ?` (or `DELETE`) makes the coordinator build all P × Q rows
(`ModificationStatement.addUpdates` ← `getMutations`) on one request thread before anything is applied; the
`in_select_cartesian_product` guardrail ships at −1 and, when enabled, bounds P and Q separately; a 176 KB request builds
4 × 10⁷ rows and OOMs a 2 GiB heap.

**Label: `client-triggerable · data role; coordinator, repeatable on every node`**

**Condition:** none.

## Blast radius

- **Which node:** the coordinator the attacker connects to (the rows are built there before any replica is contacted).
- **Repeatable:** yes, one 176–480 KB request per node, every node.
- **Other tenants:** the coordinator dies (2–4 GiB) or sits in ≥ 90 % STW for as long as measured (8–16 GiB: 500 s and
  1,220 s); clients on it time out or lose connections; its replicas' ranges lose a replica. Note: the shipped
  `OnOutOfMemoryError` kill did not fire in U7's runs, so the node may stay up but unusable until killed.

## Operator visibility

None before the failure: no guardrail warning (off), no write applied (memtables 0), in-flight charge 176 KB. With
authentication and audit/FQL logging on, the role and statement are attributable afterwards.

## 3-b confirm

Partly done in stage 2: `IA-1..3` ran the test arm as a non-superuser with `PasswordAuthenticator` (but
`AllowAllAuthorizer`) and OOMed 3/3. A full confirm adds `CassandraAuthorizer` with MODIFY only on `u7.t` and a victim
role; low priority given IA.

## Reason

Every step is a single prepared write with two bound lists that any role with MODIFY on an ordinary (pk, ck) table can
send; nothing else (data, fault, operator action, diagnostic aid) is in the verified arm, and the case's own IA arms show
the OOM as a non-superuser under password authentication. The only counting control is off for everyone at defaults and
per-side when on. Lowest privilege: data role (MODIFY); the coordinator dies and the attack repeats on every node.
