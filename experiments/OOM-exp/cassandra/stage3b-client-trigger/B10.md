# B10 — stage 3-b client trigger check (2026-11-24)

**Case:** [`native_transport_receive_queue_capacity--refused-v5-request-uncharged-drift`](../cases/native_transport_receive_queue_capacity--refused-v5-request-uncharged-drift/native_transport_receive_queue_capacity--refused-v5-request-uncharged-drift.md)
(true positive, `verified-OOM · deployment`; heap 2 GiB 3/3, also 4 and 8 GiB 3/3; x86 `pc72`). Stage 3-a: pending (`—` in
`_INDEX.md`). Analysis only (no node run), by a fresh session that did not design or verify the case. Code references are
to the pinned 5.0.9 tree, paths below `src/java/org/apache/cassandra/`.

**Mechanism.** In the default non-throwing mode a v5 one-frame request that fails `acquireCapacity` is still decoded and
queued on `Native-Transport-Requests` without its bytes being charged, and its release subtracts what was never added
(`transport/CQLMessageHandler.java:222-224`, `:245-260`, `:506-510`). With slow requests occupying the 128 NTR threads, the
decoded backlog grows to connections × client window: 15,220–15,404 decoded 125 KB requests (25.5 × the contract) at 2 GiB
→ `Java heap space`, dump, `kill -9`.

**Label: `client-triggerable · data role; coordinator, repeatable on every node`** — SELECT on a table holding enough rows
for a slow `ALLOW FILTERING` scan (the verified arm: one 200,000-row partition, 5.7 MB), or SELECT + MODIFY to write such
a partition itself.

**Lower privileges.** *Login role, no grants:* unauthorized SELECTs fail at once on the NTR thread, so the threads never
stay busy and no backlog forms (no slow request is available without a grant; the always-readable `system.local`/`peers`/
`system_schema` tables, `service/ClientState.java:77-93`, are small). *Pre-auth:* v5 one-frame requests from an
unauthenticated connection are decoded and queued the same way (R13 confirm PF-1: 142 k pre-auth BATCHes decoded, then
refused on NTR threads), so once something else keeps the 128 NTR threads busy — the attacker's own data-role reads, or a
node already saturated by legitimate slow requests — the queued bytes could be pre-auth filler. That needs either the data
role anyway or an outside load condition; not tested.

## Condition and how common

None beyond the defaults (reach **alone**). The prerequisite is a readable table on which a filtering read takes hundreds of
milliseconds; most production tables qualify, and with MODIFY the attacker builds one in seconds.

## Blast radius

- **Which node:** the coordinator the attacker connects to (decoded requests live there); the attacker picks it.
- **Repeatable:** yes, every node in turn or at once (≈ 23–31 s per node at 2 GiB, 20 connections from one host).
- **Other tenants:** the node dies (`kill -9` on OOM) and needs an operator restart; every client of it loses its
  connections; while the backlog builds, all requests on that coordinator wait behind 15 k queued requests (time-outs
  after 12 s), and the replicas of the scanned data run their ReadStage saturated.

## Operator visibility

`system.log` logs "Request breached limit(s) on bytes in flight (Endpoint: …, Global: …) and triggered backpressure";
`ClientMetrics` `TimedOutBeforeProcessing` rises and NTR `PendingTasks` reaches ≈ connections × window; filtering reads may
appear in the slow-query log. The connections carry the authenticated role (`system_views.clients`), so the attack is
attributable and the role can be revoked; audit logging ships off.

## 3-b confirm

**Worthwhile.** Run `T2` (2 GiB, 20 connections × 1,024, 125 KB value) with `PasswordAuthenticator` +
`CassandraAuthorizer`: admin creates and loads `ks.t` (200 k-row partition), attacker role with **SELECT only** on
`ks.t`, NativeFlood with SASL PLAIN login added; a victim role on its own table measuring success rate and latency. Two
things to watch: (1) U7's lesson — with `CassandraAuthorizer` the roles/permissions caches reload during the GC spiral and
can abort requests, which would drain NTR threads faster and might turn the OOM into GC service loss; (2) record whether
the bypass branch (`warned`, "breached limit" lines) is reached as before. Optional arm: the same with a pre-auth filler
connection set, to test the pre-auth note above.

## Reason

Every step of T2 is ordinary client behaviour: v5 connections with the drivers' default window, a SELECT with
`ALLOW FILTERING` on data the role may read, and the default non-throwing overload mode. The bypass is in the transport
layer, before authorization, so the only privilege needed is the one that makes the requests slow: SELECT on a table with
enough rows (or MODIFY to write them). No operator-side condition is involved, and the coordinator chosen by the
attacker is the node that dies.
