# R13 — stage 3 JIRA check (2026-11-23)

**Case:** [`native_transport_max_request_data_in_flight--v5-tiny-value-batch-decode-expansion`](../cases/native_transport_max_request_data_in_flight--v5-tiny-value-batch-decode-expansion/native_transport_max_request_data_in_flight--v5-tiny-value-batch-decode-expansion.md)
(true positive, `verified-OOM · deployment`).

**Mechanism checked (§4).** The native in-flight limit (`native_transport_max_request_data_in_flight`, heap/10) charges a v5
request's wire body bytes, but `BatchMessage` decode copies every bound value into its own `byte[]` + `HeapByteBuffer` on the
event loop (`CBUtil.readValueList` / `readBoundValue`), ≈ 10× the wire size for one-byte values, before any batch check; 14
admitted 15.8 MB batches (206 MB charged) hold ≈ 2 GiB.

**Label: `known-fixed (not in 5.0.9)` (partial: CASSANDRA-20166)** — qualified: 20166 reports the decode expansion of bound
values in batch/modification requests and its 6.0 fix **reduces** it (no `ByteBuffer` wrapper per value), but leaves one `byte[]`
per value (≈ 5× the wire bytes for one-byte values) and the wire-byte charge unchanged. No issue reports the in-flight accounting
gap or an OOM from it; the accounting half of the mechanism is unreported.

## Reason

The new search on decode allocations (query 9) found CASSANDRA-20166, which stage 1 did not cite: it is the decoded bound-value
holder of this case, for the same request shape (prepared batches with small bind values), reported as "more space than the data
received". It does not report an OOM or the in-flight limit's unit, so it is **partial**, not exact. Its fix is in 6.0 only
(`git merge-base --is-ancestor 8a72868066 cassandra-5.0.9` → false). By the stage-3 rule the label is `known-fixed (not in 5.0.9)`;
the fix would roughly halve R13's per-value heap (it drops the ≈ 48 B `HeapByteBuffer`, keeps the 24 B `byte[1]` and the
per-statement objects), so a 6.0 node should still admit several times its wire charge for this shape — the mechanism is reduced,
not closed. Everything else (message size, request queue, request metrics) is related only, as stage 1 found.
