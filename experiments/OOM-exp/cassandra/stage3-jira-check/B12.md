# B12 — stage 3-a JIRA check (2026-11-24)

**Case:** [`paxos_cache_size--weigher-omits-partition-key`](../cases/paxos_cache_size--weigher-omits-partition-key/paxos_cache_size--weigher-omits-partition-key.md)
(true positive, `verified-OOM · deployment`; 2 GiB 3/3, 4 GiB 3/3, aarch64).

**Mechanism checked (§4).** The Paxos state cache `PaxosState.RECENT` (Caffeine, `maximumWeight` = `paxos_cache_size`,
auto 20 MiB at a 2 GiB heap) weighs an entry only by the stored updates' `unsharedHeapSize()`
(`PaxosState.java:74`): 128 B for a v1 `SERIAL` read of an absent partition, whatever the key size. The entry's
`PaxosState.Key` keeps the cloned partition key (up to 65,535 B, no guardrail) and ≈ 600 B of shells, all uncharged, so
distinct-key `SERIAL` reads with 60 KiB keys fill the heap (≈ 490 × the weight per entry) at K ≈ 3.4 MB ≤ C.

**Label: `new`** (best match related: CASSANDRA-4315, the same defect class fixed for the key cache in 1.2)
