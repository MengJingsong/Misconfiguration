# U8 — stage 3 JIRA check (2026-11-23)

**Case file:** [`../cases/vector_dimensions--select-json-element-slices/vector_dimensions--select-json-element-slices.md`](../cases/vector_dimensions--select-json-element-slices/vector_dimensions--select-json-element-slices.md)
(verdict true positive; `verified-OOM · deployment`, unprotected).

**Mechanism checked (case §4).** `SELECT JSON` of one large vector cell: `VectorType.toJSONString` first `split()`s the
whole cell into an `ArrayList` of one `HeapByteBuffer` slice per element (≈ 52 × the serialized bytes for 1-byte
`boolean` elements) and keeps it while building the JSON string, on the native-transport request thread. Only serialized
bytes are checked (`max_mutation_size`, frame size); the `vector_dimensions` guardrail ships off (−1); concurrent renders
are bounded only by the 128 request threads → Java heap OOM.

**Label: `new`**

No issue reports `toJSONString`/`split()`/`unpack()` materializing one buffer per element, or any heap OOM from
`SELECT JSON` / `toJson()` on vectors. Trunk (2026-11-21) still does it: `VectorType.toJSONString` at trunk line 301,
`List<V> split = unpack(value, accessor)` (commit history since 5.0.9 touches `VectorType.java` only for
CASSANDRA-21536, 8a72868066 and 94c2ec3c96, none on this path).

**Documented:** no. `conf/cassandra.yaml:2183-2186` ("Guardrail to warn or fail when creating a vector column with more
dimensions than threshold. Default -1 to disable.") names the control but no memory hazard. Side finding:
`doc/modules/cassandra/pages/reference/vector-data-type.adoc:15` says "Vectors are limited to a maximum dimension of 8K
(2^13) items." — 5.0.9 does not enforce that (the case's 16,000,000-dimension column was accepted), so the shipped doc
states a limit that does not exist rather than warning about the behaviour.

**Reason.** The search covered the holder (`VectorType`, `toJSONString`, `split`, `MultiElementType`/`VectorSerializer`),
the trigger (`SELECT JSON`, `toJson`), the control (`vector_dimensions`, dimension limits) and the symptom (OOM/heap with
vector/JSON), plus all vector bugs filed since 2025 and everything filed since 2026-11-01. Only the type itself (18504),
its disabled guardrail (18730) and unrelated validation/SAI issues come up. No exact or partial issue, no shipped doc
warning (the one doc sentence on dimensions claims an 8K limit that is not enforced), so the case stays **new**, as stage 1
found (2026-11-18).
