# R20 — stage 3 JIRA check (2026-11-23)

**Case:** [`ErrorCollector_errorMsgs--humongous-trigger-matched-set-4GiB`](../cases/ErrorCollector_errorMsgs--humongous-trigger-matched-set-4GiB/ErrorCollector_errorMsgs--humongous-trigger-matched-set-4GiB.md)
(true positive, `verified-OOM · deployment`).

**Mechanism checked (§4).** The CQL lexer reports every unmatched character of a query and `ErrorCollector` keeps each message
in an unbounded `LinkedList` (`errorMsgs`, ≈ 138 B per character, ≈ 2.2 GB per 16 MiB query) although only the first is used;
the in-flight reserve counts the 16.8 MB wire body (U/K 64–88). The retained messages leave 1–6 free regions, and the next large
request's humongous decode buffer (`CBUtil.decodeString` → `CharBuffer.allocate`) fails → heap OOM.

**Label: `new`** (closest: related only).
