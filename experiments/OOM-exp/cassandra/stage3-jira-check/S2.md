# S2 — stage 3 JIRA check (2026-11-23)

**Case file:** [`../cases/convergence/coordinator-local-write-backlog--combo/coordinator-local-write-backlog--combo.md`](../cases/convergence/coordinator-local-write-backlog--combo/coordinator-local-write-backlog--combo.md)
(verdict true positive; A, G1, G2 `verified-OOM · deployment`, unprotected accumulation).

**Mechanism checked (case §4).** A coordinator that is also a replica submits its own write as a `LocalMutationRunnable`
to `Stage.MUTATION`, whose queue is unbounded. At CL=ONE the client is answered as soon as another replica acks, so the
client slot and the native in-flight byte charge are released while the local write is still queued; an expired local
write is resubmitted as a hint on the same stage, not shed. The backlog (≈ 61–63 k queued `Mutation`s, ≈ 90 % of a 2 GiB
heap) grows with offered rate − local apply rate and persists after the client stops → heap OOM.

**Label: `known-open (partial: CASSANDRA-19958, CASSANDRA-13213)`**

**Documented:** no. `conf/cassandra.yaml:1306-1317` warns that high server-side timeouts let operations build up memory
("operations that use too much CPU/read too much data (leading to memory build up)"), but S2 uses default timeouts and the
text does not cover a queued local-write backlog at CL=ONE; nothing in `doc/` or `NEWS.txt` on `MutationStage` queue size.

**Reason.** The core of S2, the unbounded `MutationStage` queue piling up local mutations, is reported in the open
CASSANDRA-19958 (still Needs Committer; no activity since 2025-04) and an OOM from pending mutations in the open
CASSANDRA-13213, so S2 is mentioned with partial matches. Neither reports S2's trigger: the CL=ONE early release by a
faster (or simply ack-first) replica, which removes every client-visible limit, plus the expired-write-to-hint
resubmission on the same stage, leading to heap OOM at defaults. 19958's patch separates hints from mutations but leaves the
local-mutation queue unbounded (from the issue text, not tested). No newer issue on point.
