# C10 — stage 3 JIRA check (2026-11-23)

**Case:** [`../cases/max_concurrent_range_requests--empty-first-batch-full-page-fanout/max_concurrent_range_requests--empty-first-batch-full-page-fanout.md`](../cases/max_concurrent_range_requests--empty-first-batch-full-page-fanout/max_concurrent_range_requests--empty-first-batch-full-page-fanout.md)
(verdict true positive, `verified-OOM · deployment`, convergence (multiplicity)).

**Mechanism checked (case §4).** Holder: sub-range read responses held on the coordinator heap until a page is assembled
(`SingleRangeResponse` / `DataResolver` arrays), uncharged after the internode receive reserve is released. Trigger: a
paged `ALLOW FILTERING` range read whose first batch returns no rows, so `RangeCommandIterator` jumps to
min(ranges, `cassandra.max_concurrent_range_requests` = 10 × cores) sub-range requests, each with the full 5,000-row page
limit; several such queries at once. Controls: the cap counts requests per query, not bytes; nothing sums across
queries; read-size thresholds ship off.

**Label: new**

## Documented

**no.** `cassandra.max_concurrent_range_requests` is not mentioned in `conf/`, `doc/`, `NEWS.txt` or `CHANGES.txt` (grep).
`conf/cassandra.yaml:2014-2020` documents the coordinator read-size threshold as off by default ("# read_thresholds_enabled:
false # scheduled to be set true in 4.2"; "this tracks the materialized size of a query on the coordinator") but gives no
warning about range-read fan-out memory.

## Reason

Stage 1's searches were rerun (hit counts unchanged except tokenizer noise) and extended with code identifiers
(`computeConcurrencyFactor`, `SingleRangeResponse`, `RangeCommandIterator` + memory) and symptom searches. The fan-out burst
is known only as a remote-request count / performance issue (15752 added the count cap, 15774 open to reduce request
count); range-read OOM reports concern one large page or unpaged result (a different holder). No issue names this holder
and trigger or reports an OOM from it, so no exact or partial match, and nothing in the shipped docs warns about it. Hence
**new**.
