# B15 — stage 3-a JIRA check (2026-11-24)

**Case:** [`commitlog_max_outstanding_replay_bytes--smaller-heap-restart`](../cases/commitlog_max_outstanding_replay_bytes--smaller-heap-restart/commitlog_max_outstanding_replay_bytes--smaller-heap-restart.md)
(true positive, `verified-OOM · deployment`, owner-accepted 2026-11-18; 1 GiB replaying heap 3/3, largest failing 1,280 MiB).

**Mechanism checked (§4).** Commit-log replay re-applies what the **writer's** memtable pool held (≈ 2.08 GiB of
memtable charge from an 8 GiB writer), not anything sized by the replaying JVM. A node restarted at a 1 GiB heap while
its data disk stalls (dm-delay) blocks all 32 appliers on the 256 MiB replay pool; the reader keeps queueing
deserialized mutations under the bound in `CommitLogReplayer.handleMutation` (1,024 mutations / 64 MiB), which counts
**serialized** bytes: 741 queued P64 mutations = K 46 MiB (≤ C) holding U ≈ 666 MiB → `OutOfMemoryError: Java heap
space` during start-up. Holder = the replay queue of deserialized mutations (as B8); new element = the replay volume
set by the writer's heap.

**Label: `known-fixed (incomplete)`** (partial: CASSANDRA-8639; its fix in 5.0.9 bounds serialized bytes, not heap; no
issue reports the writer-heap replay volume)

## Reason

The heap under-count that turns B15's replay backlog into an OOM is the CASSANDRA-8639 mechanism, whose fix is in 5.0.9
(`git merge-base --is-ancestor 1c41a9ac2c cassandra-5.0.9` → true) but counts serialized bytes rather than the heap size
the issue proposed, so it does not cover the mechanism → `known-fixed (incomplete)` under the owner's 2026-11-23 ruling
(as B8). 8639 is rated partial rather than exact because B15's trigger, a replay volume set by the writer's larger heap
(OC-59), is not reported by 8639 or by any other issue; that part is new. This differs from stage 1's prior-art verdict
(`new` for the OC-59 shape), which predates the 3-a rules: a partial issue with an incomplete fix in the pinned version
now decides the label. The replay bound is unchanged on trunk (no newer fix).
