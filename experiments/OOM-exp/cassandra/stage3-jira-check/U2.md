# U2 — stage 3-a JIRA check (2026-11-24)

**Case:** [`native_transport_max_concurrent_connections--prelogin-frame-multiplicity`](../cases/native_transport_max_concurrent_connections--prelogin-frame-multiplicity/native_transport_max_concurrent_connections--prelogin-frame-multiplicity.md)
(true positive, `verified-OOM · deployment`).

**Mechanism checked (§4).** Each unauthenticated v4 connection that sends a header declaring a 16 MiB − 9 B body and all but
the last byte pins one 16 MiB Netty pooled direct chunk in the pre-STARTUP cumulation buffer (`InitialConnectionHandler`'s
`Envelope.Decoder`), charged by no Cassandra counter. `native_transport_max_concurrent_connections` ships −1 (the
`ConnectionLimitHandler` is not even in the pipeline), there is no idle/auth timeout, so ≈ 927 such connections reach Netty's
direct limit; the `OutOfDirectMemoryError` goes through `PreV5Handlers$ExceptionHandler` → `JVMStabilityInspector` → forced heap
OOM → shipped `kill -9`.

**Label: `known-fixed (not in 5.0.9)` (partial: CASSANDRA-21755, fix 5.0.10 / 6.0-alpha3)** — the issue reports that an
unauthenticated client can make the server hold up to 16 MiB of STARTUP payload "per connection, multiplied by however many
connections it opens"; its fix (`5f11d4bd5c`, not in 5.0.9) caps **every** pre-STARTUP message, not only STARTUP, at
`StartupMessage.maxEncodedSize()` (≈ 80 KiB by default), which removes U2's 16 MiB stalled frame. Stage 1's `known-open`
(CASSANDRA-21756, CASSANDRA-4265) is superseded: those two are related only.

## Reason

Stage 1 rated U2 `known-open` on 21756 (auth timeout, open) and 4265 (Thrift, Won't Fix). Neither reports this holder: 21756
has no memory content and 4265 is the Thrift frame buffer, so both are related. The search on "unauthenticated" (query 3) found
CASSANDRA-21755, filed after stage 1's survey: its discussion names U2's root cause and trigger (pre-auth 16 MiB per connection ×
any number of connections) for the retained STARTUP options, and its fix — committed 2026-10, fix version 5.0.10, not in 5.0.9
(`git merge-base --is-ancestor 5f11d4bd5c cassandra-5.0.9` → false) — bounds every pre-STARTUP envelope in the initial decoder,
including U2's stalled OPTIONS-sized-header frame. Partial (reported holder differs; no OOM), fixed upstream, not in the pinned
version → `known-fixed (not in 5.0.9)`. Residual after the fix (reading, not run): ≈ 80 KiB per stalled connection, so the
direct limit would need ≈ 200,000 connections at 15.5 GiB; the connection limit still ships −1 and no auth timeout exists.
